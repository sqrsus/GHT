# GHT v1.5.0

本版把**默认参数改成「可用性优先」**：只要能连上 GitHub，宁可首连多花一两秒，也不要在「其实连得上」的候选上提前放弃。

## 一、默认参数调整

| 参数 | 1.4.0 | 1.5.0 | 作用 |
|---|---:|---:|---|
| `ConnectBudgetMs` 首连预算 | 3000 | **12000** | 必须大于单地址建连超时，否则一次尝试还没得出「连不上」的结论就被整体取消 |
| `RaceConnectTimeoutMs` 建连超时 | 5000 | **8000** | 跨境链路在丢包/拥塞时握手花 5~7 秒并不罕见 |
| `RaceBatchBudgetMs` 批预算 | 3000 | **9000** | 必须 ≥ 单地址超时；小于它会把还没试完的地址一起取消 |
| `RaceRetryRounds` 重赛轮数 | 2 | **3** | 后台扫描补齐新 IP 后多一轮机会 |
| `RaceRetryDelayMs` 重赛等待 | 800 | **1500** | 给后台扫描留出补候选的时间 |
| `FirstBatchCollectMs` 首批窗口 | 600 | **1200** | 窗口太短时首批只有国内 DNS 的趋同答案，候选常常只剩一个 |
| `DnsScanTimeoutMs` DNS 超时 | 2000 | **3000** | 池里不少境外解析器在 2000ms 内答不完 |
| `DnsCacheMin/MaxTtlSec` 缓存 TTL | 60 / 600 | **300 / 1800** | 少反复解析，已验证可用的地址继续复用 |

三个预算参数现在构成一组相互约束的组合，改其中一个必须同时检查另外两个：

```
ConnectBudgetMs (12000) >  RaceConnectTimeoutMs (8000)   # 总预算要够一次尝试得出结论
RaceBatchBudgetMs (9000) >= RaceConnectTimeoutMs (8000)  # 批预算不能先于单地址超时到期
RaceBatchBudgetMs (9000) <  ConnectBudgetMs (12000)      # 否则批预算永远不会生效
```

违反第一条时的现象非常固定：日志里反复出现「首连预算用尽，回落系统 DNS」，而每个地址都还没到自己的超时就被取消了——既拿不到连接，也拿不到「这个地址不行」的结论。1.5.0 起 `SettingsTests` 里有一条用例专门守这组关系，默认值被改坏会直接让 CI 失败。

> **升级不会覆盖你已有的 `settings.json`**：上面的默认值只对「文件里没有这个字段」或「点了参数区『恢复默认值』」的情况生效。想让本机也用上这套值，在界面上点一次「恢复默认值」（只重置参数区那几项，不动加速池与白名单）。

## 二、应用图标

- 新增 `src/GHT/Resources/app.ico`，含 16/20/24/32/40/48/64/128/256 共 9 帧，小尺寸做了光学放大（否则 16px 会缩成一个小黑点）。
- **exe 的 Win32 图标、窗口标题栏、托盘**三处共用同一份，不再出现「任务栏一个图标、托盘另一个图标」。
- 托盘图标不再使用系统默认的通用图标；图标句柄与它依赖的流随托盘一起释放。

## 三、其他修正

- `SettingsStore.Normalize` 的越界兜底值改为引用 `AppSettings` 的默认值，不再各抄一份字面量——避免「默认值改了、越界回退还是老值」。
- 测试 182 → **183** 例（新增默认值自洽性校验）。

## 四、产物校验

```
certutil -hashfile GHT.exe SHA256
```

与压缩包内的 `SHA256SUMS.txt` 对照即可。产物未做代码签名（仓库无可用证书），不提供「看起来像签名」的东西。

**运行要求**：Windows 10 build 17763 及以上 x64；框架依赖版需要 [.NET 8 桌面运行时](https://dotnet.microsoft.com/download/dotnet/8.0)。
