# GHT v1.6.0

本版只做一件事：**把「能跑」变成「能长期挂着跑」**。功能面没有新增，改的是内存上界、对象回收时机和可观测性 —— 这些问题在短时间试用里看不出来，只有连开几天才会显现。

## 一、并发连接终于有上限了

旧实现的接入循环对每条连接都无条件 `Task.Run`，活跃连接数完全由客户端行为决定。按一条隧道 600KB–1MB 的受控内存（两个 32KB 转发缓冲 + 两端各 256KB 套接字缓冲 + 任务与状态）估算，几百条并发就是几百 MB，而且没有任何刹车。

| 新配置 | 默认值 | 含义 |
|---|---:|---|
| `MaxConcurrentConnections` | **512** | 全局并发上限，超出返回 503；`0` = 不限 |
| `MaxConnectionsPerHost` | **64** | 同一上游主机的并发隧道上限；`0` = 不限 |

两个细节值得说清楚：

- **超限回 503，不是静默断开**，但拒绝路径本身也有界：只有拿到 16 个拒绝槽位之一时才写响应，拿不到就直接关连接。否则「拒绝」会变成新的内存压力源 —— 每写一个响应都要一个任务。
- **单主机上限不是按客户端 IP 分组的**。本代理只监听回环，所有客户端都是 `127.0.0.1`，按客户端 IP 分组等于让这个上限完全失效。真正的风险源是「同一个上游被并发打满」，所以按目标主机分组，且计数归零时条目立即从字典移除。

界面上「参数设置」多了一个「最大连接数」输入框，改完失焦即生效。

## 二、会一直长大的四张表

| 表 | 原来 | 现在 |
|---|---|---|
| 在飞扫描 `_sweeps` | 只有「下次解析同域名」才顺手清理，高频访问不同域名时只增不减 | **扫描一结束就按 key+value 精确移除**，另加 2048 条兜底与完成项清理 |
| 地址健康度 `_health` | 无上限 | 4096 条上限；30 天未出现即淘汰；写盘只保留最近 2048 条且直接在流上序列化 |
| DNS 健康度 `_serverHealth` | 换池后旧服务器永远留着 | 2048 条上限；1 小时无活动即淘汰 |
| 地址 → 来源 `_ipSource` | 超限时整表 `Clear()` | 按插入顺序淘汰 1/4，不再让失败归因整段丢失 |

其中扫描表是最实在的一处：每一项都攥着 `Task`、候选表与首批快照。

## 三、少分配，而不是只加上限

- **域名缓存**单域名封顶 64 个地址（超限时按「最早过期」淘汰，而不是按地址字面值截断）；排序键（地址字节）在合并时算一次，不再让比较器在 O(n log n) 次比较里反复 `GetAddressBytes()`。
- **合并快路径**：答案全是已知地址且现有地址都没过期时，只顺延 TTL，不重建字典、地址数组，也不排序 —— 长跑时这是最高频的一条路径。
- **日志**：最近日志缓冲从「只限 500 条」改成「500 条 **且** 512K 字符」双重上限；写盘队列从 8192 收到 2048。最坏情况从约 35MB 降到约 17MB。
- **竞速**：落败任务的等待上限从 2s 收到 1s（取消后正常路径几十毫秒就结束），不再让「胜出后还要干等 2 秒」变成常态。

## 四、运行期指标

状态栏第二行新增一行（每秒刷新，全部 O(1) 读数）：

```
内存 62.4MB · 分配 3.1MB/s · GC 12/3/1 · 连接 14/512（拒绝 0） · 缓存 6 · 扫描 0 · DNS 88 · 地址 120 · 来源 40 · 日志 0 · 线程池排队 0
```

判读只有一条原则：**跑几小时后，任何一项单调增长都说明有一处没被回收**。「扫描」应随时回到 0 附近，其余几项应稳定在一个量级。需要更细的基线时用 `dotnet-counters`，命令写在 README 的「运行期观测」一节。

## 五、测试

183 → **199** 例，新增的一组 `MemoryBoundsTests` 专门守这些上界：

- 全局/单主机名额的占满、拒绝、归还与归零回收；
- 单域名地址数封顶、条目表在「所有条目都新鲜」时仍有硬上限；
- 地址健康度到 4096 条后仍能被淘汰，且不会把有效记录一起清掉；
- 200 个不同域名解析完后，扫描表回落到个位数；
- 日志缓冲的字符上限；
- 两条真实 socket 的集成用例：全局超限回 503、单主机超限回 503。

## 六、产物校验

```
certutil -hashfile GHT.exe SHA256
```

与压缩包内的 `SHA256SUMS.txt` 对照即可。产物未做代码签名（仓库无可用证书）。

**运行要求**：Windows 10 build 17763 及以上 x64；框架依赖版需要 [.NET 8 桌面运行时](https://dotnet.microsoft.com/download/dotnet/8.0)。
